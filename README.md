# 🐧 پینگینو | ربات فروش کانفیگ و مینی‌اپ

منوی فارسی تلگرام + فروشگاه وب راست‌به‌چپ، متصل به HS Panel. قیمت‌ها، کاربران، سفارش‌ها و حق تست در ربات و مینی‌اپ **مشترک و ماندگار** هستند.

## امکانات

- **عضویت اجباری در [کانال پینگینو](https://t.me/pingino_org)**: لینک عضویت و دکمهٔ «عضو شدم؛ بررسی کن». وضعیت واقعی با `getChatMember` بررسی می‌شود؛ خطای تلگرام مجوز ورود محسوب نمی‌شود.
- منوی دائمی پایین چت، دکمه‌های اینلاین و فرمان‌های `/start`، `/menu`، `/trial`، `/myconfigs`، `/orders`، `/help`، `/cancel` و `/admin`.
- **تست رایگان یک‌روزه، پیش‌فرض ۱ گیگ**؛ یک‌بار برای هر حساب تلگرام، حتی بعد از ری‌استارت. حق تست فقط پس از ساخت موفق مصرف می‌شود.
- کاتالوگ‌های جدا برای **کانفیگ عادی و گیمینگ**؛ امکان اتصال هر دسته به پنل/پروتکل جدا.
- ادمین در تلگرام یا داشبورد وب می‌تواند **قیمت، حجم، مدت، نام و فعال‌بودن پلن** را تغییر بدهد. حجم، دسته و وضعیت تست هم قابل تغییر است؛ مدت تست همیشه ۲۴ ساعت می‌ماند.
- فاکتور با قیمت و حجم ثابت زمان ثبت، کارت‌به‌کارت، دریافت عکس رسید در ربات، نمایش خود عکس به ادمین و تأیید/رد پرداخت.
- کانفیگ‌های من، تاریخچهٔ سفارش، راهنمای دستگاه‌ها، پشتیبانی و **تمدید همان اشتراک بدون عوض شدن لینک**.
- آمار، صف رسیدها، کاربران و ارسال همگانی با پیش‌نویس و تأیید نهایی در ربات.
- مینی‌اپ واکنش‌گرا: رنگ بنفش/سبز، فونت محلی وزیرمتن، ماسکات پینگینو، حالت روشن/تاریک، نمایش عضویت، فیلتر و جستجوی سفارش، کپی لینک، فرم‌های واقعی مدیریت.
- احراز هویت مینی‌اپ با بررسی **امضای Telegram `initData` روی سرور** و انقضای نشست؛ نقش ادمین فقط از `admin_ids` تعیین می‌شود.
- جلوگیری از تأیید/تست تکراری، حفظ سفارش در خطای پنل و بازیابی کنترل‌شدهٔ درخواست‌های مبهم.

> رنگ دکمه‌های تلگرام از `style`های رسمی `primary`، `success` و `danger` استفاده می‌کند؛ نمایش دقیق تابع نسخه و تم کلاینت است. برای Bot API محلی قدیمی، `colored_buttons` را `false` کنید. مینی‌اپ رنگ‌بندی مستقل و کامل دارد.

## نصب و تنظیمات واقعی

Python **3.11 یا بالاتر**:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp config.example.json config.json
```

فایل `config.json` را **روی سرور خودتان** تنظیم کنید:

| گزینه | توضیح |
|---|---|
| `bot_token` | توکن ربات از BotFather؛ محرمانه |
| `admin_ids` | آرایهٔ آیدی عددی ادمین‌ها، مانند `[123456789]`؛ یوزرنیم نیست |
| `panel_url`, `panel_password` | آدرس و رمز پنل HS واقعی |
| `card_number`, `card_name` | اطلاعات مقصد کارت‌به‌کارت؛ پیش‌فرض خالی است تا کسی به شمارهٔ ساختگی پول واریز نکند |
| `support_username` | نام کاربری واقعی پشتیبانی بدون `@` |
| `webapp_url` | آدرس عمومی **HTTPS** همین فروشگاه، مثلاً `https://shop.your-domain.example` |
| `bot_username` | نام کاربری ربات بدون `@`؛ هنگام اتصال موفق به تلگرام نیز خودکار شناسایی می‌شود |
| `required_channel` | پیش‌فرض `@pingino_org`؛ برای کانال خصوصی از شناسهٔ عددی و لینک دعوت متناظر استفاده کنید |
| `required_channel_url` | پیش‌فرض `https://t.me/pingino_org` |
| `panel_profiles` | تنظیمات اختیاری اتصال هر دسته، توضیح پایین |

**مهم: ربات را در `@pingino_org` ادمین کنید.** بدون این دسترسی، بررسی قابل اتکای عضویت سایر کاربران ممکن نیست. کاربران باید ربات را در چت خصوصی استفاده کنند. ادمین نیز برای امکانات کاربری باید عضو باشد؛ فرمان مدیریتی `/admin` برای رفع مشکلات تنظیمات به عضویت وابسته نیست، اما همیشه نقش ادمین را بررسی می‌کند.

### متغیرهای محیطی

به‌جای فایل یا برای جایگزینی بعضی مقادیر، `.env.example` را به `.env` کپی کنید. `BOT_TOKEN`، `BOT_USERNAME`، `ADMIN_IDS` (با کاما)، `PANEL_URL`، `PANEL_PASSWORD`، `WEBAPP_URL`، `SUPPORT_USERNAME`، `CARD_NUMBER` و `CARD_NAME` پشتیبانی می‌شوند.

متغیرهای حاضر در محیط نسبت به فایل اولویت دارند؛ متغیرهای خالیِ غیرضروری را از `.env` حذف کنید تا مقدار فایل را خالی نکنند. **توکن و رمز را در چت، سورس، اسکرین‌شات یا Git ثبت نکنید.**

## اجرا

### ربات + مینی‌اپ با هم (پیشنهادی)

```bash
python run.py
```

سرور روی `0.0.0.0:8080` بالا می‌آید. در استقرار واقعی، HTTPS را با دامنه و reverse proxy یا Fly فراهم کنید و همان URL را در `webapp_url` بگذارید. پس از ری‌استارت، دکمهٔ فروشگاه و منوی وب تلگرام خودکار تنظیم می‌شوند.

همهٔ درخواست‌های مرورگر از `/api/...` استفاده می‌کنند؛ آدرس HS Panel فقط در سرور مصرف می‌شود. هیچ توکن بات/رمز پنلی به مرورگر ارسال نمی‌شود. باز کردن مستقیم صفحه در مرورگر عمومی، به داده‌های کاربر یا مدیریت دسترسی نمی‌دهد؛ ورود واقعی از ربات است.

### فقط منوی تلگرام

```bash
python bot.py
```

مینی‌اپ اجباری نیست. اگر `webapp_url` خالی باشد، منوی فارسی تلگرام مستقل کار می‌کند.

### اجرای جداگانهٔ وب

```bash
uvicorn webapp:app --host 0.0.0.0 --port 8080
```

هر دو فرایند باید از **یک `PINGINOO_DATA_DIR`** استفاده کنند. یک توکن فقط باید یک فرایند polling داشته باشد. `run.py` را هم‌زمان با `bot.py` برای همان توکن اجرا نکنید.

## پیش‌نمایش بدون توکن و پرداخت واقعی

```bash
PINGINOO_DEMO=1 python run.py
```

سپس آدرس سرور روی پورت ۸۰۸۰ را باز کنید.

- بالای صفحه و پایین آن «نسخهٔ نمایشی» مشخص شده است.
- حساب، اشتراک، رسید و نقش ادمین همگی **نمونه** هستند.
- داده‌ها فقط در `demo-data/demo.sqlite3` ذخیره می‌شوند، نه بانک اطلاعاتی واقعی.
- سفارش، تست و تأیید ادمین در دمو قابل امتحان‌اند، ولی هیچ ارتباطی با تلگرام/HS Panel یا پرداخت واقعی ندارند.
- لینک‌های دمو عمداً از دامنهٔ نامعتبر `example.invalid` استفاده می‌کنند.
- **در محیط واقعی `PINGINOO_DEMO=0` بماند.** دمو یک ابزار عمومی نمایش است، نه روش ورود ادمین به فروشگاه واقعی.

## مدیریت قیمت و حجم

**داخل ربات:** `/admin` ← «قیمت و حجم پلن‌ها» ← انتخاب پلن ← تغییر قیمت/حجم/مدت. اعداد فارسی و انگلیسی پذیرفته می‌شوند؛ مقادیر نامعتبر ذخیره نمی‌شوند.

**داخل مینی‌اپ:** «پنل مدیریت» ← «پلن‌ها و قیمت‌ها» ← «ویرایش». فعال/غیرفعال کردن پلن، فروش جدید را کنترل می‌کند و اشتراک‌های قبلی را قطع نمی‌کند.

تنظیمات اولیه از فایل وارد می‌شوند؛ پس از اولین اجرا، **قیمت‌ها و تنظیمات تست در SQLite مرجع اصلی‌اند**. تغییر دستی `plans` یا `trial` در فایل پس از راه‌اندازی، ویرایش‌های ادمین را بازنویسی نمی‌کند. از پنل مدیریت استفاده کنید. تنظیمات اتصال، توکن، ادمین‌ها و پشتیبانی همچنان از فایل/محیط خوانده می‌شوند و تغییرشان به ری‌استارت نیاز دارد.

تغییر قیمت، حجم یا مدت به فاکتورهای قدیمی سرایت نمی‌کند؛ مبلغی که به کاربر نشان داده شده حفظ می‌شود.

## جریان پرداخت

۱. کاربر عضو کانال می‌شود و پلن را انتخاب می‌کند. ایمیل برای خرید اجباری نیست؛ ایمیل‌های قدیمی حفظ و در صورت وجود به پنل ارسال می‌شوند.
۲. فاکتور ثبت و اطلاعات کارت نمایش داده می‌شود.
۳. در مینی‌اپ، «ارسال رسید در ربات» کاربر را با deep link به همان سفارش می‌برد. در ربات نیز ارسال مستقیم عکس رسید ممکن است.
۴. **خود عکس رسید** همراه دکمه‌های تأیید/رد برای ادمین فرستاده می‌شود؛ در صف مدیریت نیز باقی می‌ماند.
۵. بعد از بررسی واقعی واریز، ادمین تأیید می‌کند. فقط ساخت/تمدید موفق در پنل موجب تأیید نهایی و ذخیرهٔ کانفیگ می‌شود.

این پروژه **درگاه بانکی و تأیید خودکار واریز ندارد**. عکس رسید به‌تنهایی اثبات واریز نیست؛ ادمین باید تراکنش بانکی را تطبیق بدهد. ارسال رسید دوباره یا کلیک چند ادمین موجب ساخت چند کانفیگ نمی‌شود. اگر ارسال پیام نهایی به کاربر ناموفق باشد، لینک در حساب او باقی می‌ماند.

## جداسازی واقعی مسیر گیمینگ

تفکیک کاتالوگ و ذخیرهٔ دسته به‌صورت پیش‌فرض فعال است. برای استفاده از سرور/پروتکل جدا، در فایل تنظیمات بنویسید:

```json
{
  "panel_profiles": {
    "regular": {},
    "gaming": {
      "panel_url": "https://gaming-panel.your-domain.example",
      "panel_password": "",
      "protocol": "vless"
    }
  }
}
```

مقدار رمز را فقط روی سرور تنظیم کنید. مقادیر خالی به تنظیمات پنل اصلی برمی‌گردند. اگر پروفایل جدا نگذارید، هر دو دسته در پنل اصلی ساخته می‌شوند اما پلن، برچسب و سفارش جدا دارند. صرفاً انتخاب نام «گیمینگ» **پینگ را بهینه یا تضمین نمی‌کند**؛ مسیر مناسب باید در خود زیرساخت HS Panel فراهم شود. آدرس پنل زمان ساخت کنار اشتراک ثبت می‌شود تا تمدید روی همان سرور انجام شود.

### قرارداد API پنل

همان قرارداد موجود پروژه حفظ شده است:

- ورود: `POST /api/login` با `password` و دریافت `token` / `access_token` / `key`.
- ساخت: `POST /api/subs` با `name`, `traffic` (بایت), `days` و در صورت وجود `email` / `protocol`؛ پاسخ باید `uuid` / `id` / `uid` داشته باشد.
- تمدید: `PATCH /api/subs/{id}` با `days` و `traffic`؛ کلاینت فرض می‌کند پنل مدت درخواستی را به اعتبار اشتراک اضافه و سهمیه را مطابق درخواست تنظیم می‌کند.
- بررسی برای بازیابی: `GET /api/subs/{id}`.
- لینک: `subscription_url` / `sub_url` / `url` از پاسخ، یا `/sub/{uuid}`.
- مسیر `/api/links` فقط در پاسخ **۴۰۴ یا ۴۰۵** به‌عنوان جایگزین استفاده می‌شود؛ نه بعد از timeout یا ۵۰۰، چون ممکن است عملیات قبلاً اجرا شده باشد.
- هر گیگ سهمیه برابر `1024**3` بایت است. در رابط، حجم پلن و زمان باقی‌مانده نشان داده می‌شود؛ **مصرف لحظه‌ای یا پینگ اندازه‌گیری‌شده ادعا نمی‌شود**.

قبل از فروش عمومی، ساخت، سهمیه و معنای تمدید را روی **نسخهٔ واقعی پنل خودتان** با یک اشتراک کم‌حجم بررسی کنید. سورس HS Panel در این مخزن نیست و تست‌های پروژه از پنل شبیه‌سازی‌شده استفاده می‌کنند.

## بازیابی در خطای پنل

- خطای قطعی قبل از ساخت: سفارش در صف می‌ماند یا حق تست آزاد می‌ماند؛ تلاش مجدد مجاز است.
- timeout، ۵۰۰ یا پاسخ بدون شناسه: وضعیت `needs_review` می‌شود تا کانفیگ تکراری ساخته نشود.
- اگر فرایند هنگام ساخت متوقف شود، وضعیت `provisioning` حفظ می‌شود. پس از **۵ دقیقه** ادمین می‌تواند بررسی کند.
- ادمین ابتدا در HS Panel، برچسب شامل دسته/کاربر/شناسهٔ سفارش (یا `trial_<user>_<reference>`)، حجم و انقضا را بررسی می‌کند. سپس از جزئیات سفارش یا کاربر، «بازیابی» را می‌زند و UUID **همان اشتراک موجود** را وارد می‌کند.
- بازیابی فقط یک درخواست خواندن می‌فرستد و لینک را ثبت می‌کند؛ دوباره ساخت یا تمدید نمی‌کند. اگر اشتراک واقعاً در پنل وجود ندارد، قبل از هر تغییر دستی وضعیت با مدیر زیرساخت بررسی کنید؛ آزادسازی خودکار درخواست مبهم عمداً وجود ندارد.

## نگهداری داده و مهاجرت

فایل‌های تولیدشده در `PINGINOO_DATA_DIR` (پیش‌فرض کنار سورس):

```text
config.json          # تنظیمات محلی اختیاری و محرمانه
pinginoo.sqlite3      # کاربران، سفارش‌ها، کاتالوگ و تست‌های دریافت‌شده
pinginoo.sqlite3-wal  # فایل کاری SQLite؛ ممکن است وجود داشته باشد
pinginoo.sqlite3-shm  # فایل کاری SQLite؛ ممکن است وجود داشته باشد
receipts/            # فقط رسیدهای نسخهٔ قدیمی، در صورت مهاجرت
demo-data/           # دیتای جداگانهٔ حالت نمایشی
```

در اولین راه‌اندازی بانک اطلاعاتی، `users.json` و `pending_payments.json` قدیمی از همان پوشه **یک‌بار و بدون حذف/تغییر فایل اصلی** وارد می‌شوند. اشتراک‌ها و فاکتورها حفظ می‌شوند. بعد از آن JSONها دیگر مرجع فعال نیستند. پیش از مهاجرت از فایل‌های قدیمی، تنظیمات و پوشهٔ رسیدها پشتیبان بگیرید.

SQLite با WAL و تراکنش‌های اتمیک بین ربات و وب مشترک است. برای استقرار یک **volume پایدار** لازم است؛ حذف بانک اطلاعاتی سابقهٔ پرداخت و محدودیت تست را از بین می‌برد. برای پشتیبان زنده از API `sqlite3.Connection.backup` استفاده کنید، نه کپی تنها فایل اصلی هنگام نوشتن:

```bash
python - <<'PY'
import os, sqlite3
from pathlib import Path
root = Path(os.getenv("PINGINOO_DATA_DIR", "."))
with sqlite3.connect(root / "pinginoo.sqlite3") as source:
    with sqlite3.connect(root / "pinginoo-backup.sqlite3") as destination:
        source.backup(destination)
PY
```

فایل پشتیبان حاوی اطلاعات خصوصی و لینک اشتراک است؛ در محل امن نگهداری کنید.

## Docker / Fly

Docker به‌صورت پیش‌فرض ربات و وب را با هم اجرا می‌کند. توکن، `.env`، داده‌ها و آرشیو غیرضروری `xray.zip` داخل image کپی نمی‌شوند.

```bash
docker build -t pinginoo .
docker run --env-file .env -p 8080:8080 \
  -v pinginoo-data:/data pinginoo
```

در صورت تنظیمات فایل، `config.json` را داخل volume در `/data/config.json` قرار دهید. HTTPS باید بیرون کانتینر فراهم شود.

در Fly، فایل `fly.toml` سرویس پورت ۸۰۸۰، health check و volume پایدار را تعریف می‌کند:

```bash
fly volumes create pinginoo_data --region fra --size 1
# تنظیم متغیرهای محرمانه با fly secrets روی سیستم خودتان
fly deploy --ha=false
fly scale count 1
```

`WEBAPP_URL` باید URL واقعی برنامه باشد. فقط **یک ماشین / polling worker** با volume مشترک اجرا کنید؛ دادهٔ این نسخه برای چند سرور مستقل طراحی نشده است. این تغییرات به‌خودی‌خود ربات را روی Fly یا تلگرام deploy نمی‌کنند.

## تست و توسعه

```bash
source .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q

ruff format --check .
```

- تست‌های Python: مهاجرت، قیمت/حجم و اعداد فارسی، حفظ فاکتور، عضویت اجباری، کنترل دسترسی، امضای مینی‌اپ، مالکیت سفارش، تست یک‌بارمصرف، تأیید هم‌زمان، تمدید، بازیابی و شکست پنل.
- تست‌های مرورگر: دسکتاپ/موبایل، انتخاب دسته، ذخیرهٔ قیمت و حجم، خرید تا تأیید و دریافت لینک، تست یک‌روزه، دروازهٔ عضویت، جستجو و راهنما، تزریق HTML و بررسی دسترس‌پذیری WCAG A/AA صفحهٔ اصلی.
- تست مرورگر داده‌های موقت جدا روی پورت ۸۰۹۱ می‌سازد؛ به توکن و پنل واقعی احتیاج ندارد. متغیر اختیاری `CHROMIUM_PATH` اجازهٔ استفاده از Chromium از پیش نصب‌شده را می‌دهد.
